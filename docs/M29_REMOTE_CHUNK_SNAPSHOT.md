# M29 Remote Chunk Snapshot

M29 adds immutable `RemoteChunkSnapshot` and the opt-in
`RemoteWorldMultiplayerSession`. The neutral snapshot exposes coordinate-based
`BlockState`, block-light, sky-light, block-count, and non-air queries. Its
constructor defensively copies every plane and rejects inconsistent sizes.

The b1.7.3 adapter reads the bounded compressed bytes from native `Packet51`,
requires zlib to finish at exactly `width * height * depth * 5 / 2` bytes, and
splits the result into block ID, metadata, block-light, and sky-light planes.
Coordinates use the mapped vanilla local order `(x * depth + z) * height + y`;
low/even and high/odd nibbles match `NibbleArray`.

The executable oracle compiles the mapped `NibbleArray.java` generated by the
pinned RetroMCP workspace and compares all 32,768 coordinates of a synthetic
full chunk. Two additional clients decode real full chunks sent by two fresh
unmodified official servers.

## Non-claims

M29 does not cache multiple chunks, apply prechunk unloads, decode entities or
tile entities, construct a native client `World`, render received terrain,
claim identical spawn content, or externally step the server tick thread.
